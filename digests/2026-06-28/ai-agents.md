## 3. 项目进展

尽管合并率较低，但在过去24小时内，项目在修复关键问题和架构演进上仍有关键动作。最重要的进展是 **`sessions.json` 和 JSONL 存储向 SQLite 重构的大型 PR (#96625) 正在推进**，这将从根本上解决长期存在的会话文件膨胀和内存泄漏问题。

- **关键修复与合并：**
    - **[PR #96317] (已关闭)** 修复了 Telegram 频道中，智能体执行多步任务时流式更新覆盖历史消息的问题。通过添加 `appendMode`，现在可以保留每一步的进度更新。
    - **[PR #96855] (已合并)** 修复了网关重启后，`reloadRoles` 可能导致初始化和配置同步失败的问题，提升了网关的健壮性。
    - **[PR #97352] (Open)** 修复了 ACP (Agent Communication Protocol) 任务取消的生命周期漏洞，包括处理重复任务行和 CLI 取消失败的问题，对多智能体协调至关重要。
- **架构演进：**
    - **[PR #96625] (Open, 等待作者)** 这是一个影响深远的架构级重构。它将所有会话元数据和转录事件存储从 `sessions.json` 和 JSONL 文件迁移到基于 SQLite 的存储。此举旨在解决 `sessions.json` 无限增长导致的内存泄漏和 OOM 问题，是提升项目稳定性的里程碑。该 PR 状态为“等待作者”，进展需密切关注。
- **安全与策略改进：**
    - **[PR #67421] (Open)** 增加了按 `agents.list` 粒度配置 `web_fetch` 工具的 SSRF 策略。这使得运维团队可以为高风险任务（如访问内部网络）的智能体授予特定权限，提高了安全性和灵活性。

## 4. 社区热点

今日社区讨论焦点高度集中于**智能体的可靠性**和**系统稳定性**问题，反映出用户对“AI 助手”的信任感出现动摇。

- **空承诺与假动作 (The Issue That Won the Day):**
    - **[Issue #58450] “Agent can promise a later follow-up without starting any actual follow-up action”** 以 15 条评论成为今日最热 Issue。用户 `al-osokin` 尖锐地指出，智能体会在对话结尾“画饼”，声称将进行后续操作但实际并未启动任何后台进程或子任务。这引发了用户对智能体行为透明度和执行可靠性的担忧，反映了当前 LLM 智能体在**任务规划与实际执行之间的脱节**问题。

    - **[Issue #92201] “Embedded runner: freshly streamed thinking signatures intermittently invalid on replay”** 同样获得 15 条评论。此问题困扰使用 Anthropic 模型的用户，智能体流式传输的“思考签名”在回放时偶尔无效，且由于错误文本过于通用，导致恢复机制无法触发，故障以静默方式发生。这直接影响了调试和审计能力，是实际部署中的“暗礁”。

- **核心稳定性持续承压:**
    - **[Issue #91588] “Critical: Gateway Memory Leak”** 作为 P0 级问题，持续受到关注。Gateway 进程内存在 2-3 天内从 350MB 暴涨至 15.5GB，引发 OOM 崩溃和重复重启循环。这是对服务稳定性的直接威胁。
